Greedy Fundamentals & Activity Selection

💰 Greedy · Important · Easy

Worst case O(n log n)Priority 4/5
← All Algorithms← Minimum Spanning Tree (Kruskal & Prim) · Fractional Knapsack →

1 · What is it?

A greedy algorithm builds a solution one choice at a time, always taking the option that looks best right now and never revisiting it. Activity selection is the canonical example: to fit the most non-overlapping activities, sort by finish time and repeatedly take the first activity that starts at or after the previous one ends. Choosing by earliest finish leaves the most room for everything that follows — a locally optimal move that is also globally safe.

2 · Why, When & How to select

Why we need it

When a problem has the greedy-choice property, greedy gives provably optimal answers in one linear scan after a sort — dramatically simpler and faster than dynamic programming. Recognising that property (and proving it with the exchange argument: any optimal solution can be swapped to include the greedy choice without loss) is a core algorithm-design skill, and activity selection is the standard first proof.

When it is needed

  • Scheduling non-overlapping intervals (meetings, jobs, broadcasts, lab equipment).
  • The problem offers an exchange argument: keeping the greedy choice never hurts optimality.
  • One sorted pass suffices and DP's extra dimension would be wasted effort.
  • A reasonably good answer fast is acceptable even where optimality is unproven (heuristics).

How to select it

  • Sort by the quantity you want to leave maximal room for — earliest FINISH for interval scheduling.
  • Prove greedy-choice + optimal substructure before trusting the result; test against brute force on small inputs.
  • Ties: any consistent tie-break is fine for activity selection (all maximal sets have equal size).
  • If greedy's answer is wrong on some case, look for DP (e.g. weighted intervals need DP, not greedy).
  • Watch boundary conditions: touching intervals (start == previous finish) are compatible here.

When NOT to use it

  • Weighted interval scheduling — earliest-finish is not optimal; DP over finish times is.
  • 0/1 knapsack — greedy by value/weight ratio fails; DP required (fractional knapsack IS greedy-safe).
  • Choices interact far in the future with no provable local guarantee — greedy can be arbitrarily bad.
  • You must guarantee optimality under adversarial inputs but cannot produce an exchange argument.

5 · Implementation (C / C++ / Python)

#include <stdio.h>

typedef struct { int start, finish; } Activity;

/* Greedy: sort by finish time, take every activity that starts at or
 * after the previous one's finish. O(n log n). */
int activity_selection(Activity a[], int n, Activity chosen[]) {
    for (int i = 1; i < n; i++) {          /* insertion sort by finish */
        Activity key = a[i];
        int j = i - 1;
        while (j >= 0 && a[j].finish > key.finish) { a[j + 1] = a[j]; j--; }
        a[j + 1] = key;
    }
    int count = 0, last = -1;
    for (int i = 0; i < n; i++) {
        if (a[i].start >= last) {
            chosen[count++] = a[i];
            last = a[i].finish;
        }
    }
    return count;
}

void print_acts(Activity a[], int n) {
    for (int i = 0; i < n; i++) printf("(%d,%d) ", a[i].start, a[i].finish);
    printf("\n");
}

int main(void) {
    Activity acts[] = {{1,4},{3,5},{0,6},{5,7},{3,9},{5,9},{6,10},{8,11},{8,12},{2,14},{12,16}};
    int n = 11;
    Activity chosen[n];
    int m = activity_selection(acts, n, chosen);
    printf("Test 1: %d activities: ", m); print_acts(chosen, m);

    Activity acts2[] = {{1,2},{2,3},{3,4}};
    Activity chosen2[3];
    printf("Test 2: %d activities: ", activity_selection(acts2, 3, chosen2));
    print_acts(chosen2, 3);

    Activity acts3[] = {{5,10}};
    Activity chosen3[1];
    printf("Test 3: %d activities: ", activity_selection(acts3, 1, chosen3));
    print_acts(chosen3, 1);
    return 0;
}

#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

struct Activity { int start, finish; };

/* Greedy: sort by finish time; take every activity that starts at or
 * after the previous finish. O(n log n). Correct by the exchange argument. */
vector<Activity> activity_selection(vector<Activity> a) {
    sort(a.begin(), a.end(),
         [](const Activity& x, const Activity& y) { return x.finish < y.finish; });
    vector<Activity> chosen;
    int last = -1;
    for (const Activity& act : a) {
        if (act.start >= last) {
            chosen.push_back(act);
            last = act.finish;
        }
    }
    return chosen;
}

void print_acts(const vector<Activity>& a) {
    for (const Activity& x : a) cout << "(" << x.start << "," << x.finish << ") ";
    cout << "\n";
}

int main() {
    vector<Activity> acts = {{1,4},{3,5},{0,6},{5,7},{3,9},{5,9},{6,10},{8,11},{8,12},{2,14},{12,16}};
    vector<Activity> c1 = activity_selection(acts);
    cout << "Test 1: " << c1.size() << " activities: "; print_acts(c1);

    vector<Activity> c2 = activity_selection({{1,2},{2,3},{3,4}});
    cout << "Test 2: " << c2.size() << " activities: "; print_acts(c2);

    vector<Activity> c3 = activity_selection({{5,10}});
    cout << "Test 3: " << c3.size() << " activities: "; print_acts(c3);
    return 0;
}

def activity_selection(activities):
    """Greedy: sort by finish time; take every activity whose start is at or
    after the previous finish. O(n log n); optimal by the exchange argument."""
    chosen = []
    last = -1
    for s, f in sorted(activities, key=lambda a: a[1]):
        if s >= last:
            chosen.append((s, f))
            last = f
    return chosen


def fmt(chosen):
    return " ".join(f"({s},{f})" for s, f in chosen) + " "


if __name__ == "__main__":
    c1 = activity_selection([(1, 4), (3, 5), (0, 6), (5, 7), (3, 9), (5, 9),
                             (6, 10), (8, 11), (8, 12), (2, 14), (12, 16)])
    print(f"Test 1: {len(c1)} activities: {fmt(c1)}")

    c2 = activity_selection([(1, 2), (2, 3), (3, 4)])
    print(f"Test 2: {len(c2)} activities: {fmt(c2)}")

    c3 = activity_selection([(5, 10)])
    print(f"Test 3: {len(c3)} activities: {fmt(c3)}")

7 · Real-world applications

📌 Meeting-room and lab scheduling

Calendar tools and booking systems fit the most sessions into shared rooms with exactly this sweep.

📌 Broadcast & advertisement slots

Maximising aired spots in fixed windows uses interval scheduling (or its weighted DP variant).

📌 Task scheduling in OS/CI runners

Greedy ordering heuristics decide job placement before more expensive optimisers run.

📌 Foundation for other greedy proofs

Huffman, MST (cut property), and fractional knapsack all lean on the same exchange-argument technique.
